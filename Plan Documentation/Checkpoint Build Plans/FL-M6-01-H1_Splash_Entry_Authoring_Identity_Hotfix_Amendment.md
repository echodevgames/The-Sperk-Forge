# FL-M6-01-H1 — Splash Entry Authoring Identity Hotfix Amendment

**Document role:** Bounded SFGSS-005 implementation-authority amendment
**Parent checkpoint:** FL-M6-01 — First Light Production Reference Showcase
**Package:** First Light — Startup and Launch (`EchoLaunch`)
**Specification:** SFGSS-PKG-ECHOLAUNCH-001 v1.14.0
**Unity baseline:** `6000.3.8f1`
**Repository baseline:** `076a623`
**Status:** Approved for bounded implementation
**Date:** August 8, 2026

---

## 1. Trigger

The Production Reference Showcase reached its real public SplashSequence authoring step.

Two entries were added through the normal Unity Inspector and every visible field was authored. Both serialized with blank hidden identities:

```text
- entryId:
  image: <EchoDevGames image>
  displayLabel: EchoDevGames Studio

- entryId:
  image: <First Light image>
  displayLabel: First Light - Startup and Launch
```

Playing `FirstLight_Showcase_Boot` then blocked before splash playback:

```text
[ELAUNCH-SPLASH-001] Splash entry 0 is invalid.
```

No package-source drift was present. The only project WIP at discovery was the edited project-owned `SplashSequence.asset` and project-owned Art content.

## 2. Existing Authority

This hotfix does not create a new stable-ID policy.

SFGSS-PKG-ECHOLAUNCH-001 v1.14.0 already states:

```text
Configuration, sequence, steps, and diagnostically referenced splash entries require stable string IDs.
IDs are generated by Editor tooling and validated for empty values and collisions.
Runtime reads but never rewrites configuration or splash assets.
```

The defect is therefore implementation non-conformance in the consumer authoring path.

## 3. Exact Authorized Change

Add only enough Editor-side authoring support to make blank SplashEntry identities self-initializing during normal `SplashSequence` Inspector authoring.

Required semantics:

```text
if serialized entryId is empty:
    entryId = Guid.NewGuid().ToString("N")

if serialized entryId is already non-empty:
    preserve it exactly
```

Additional constraints:

- Editor assembly only;
- no Runtime playback or validation change;
- no schema change;
- no migration system;
- no YAML/manual-ID workflow;
- no public identity-edit field;
- no starter splash generator/preset;
- no automatic rewrite of non-empty malformed IDs;
- no automatic rewrite of duplicate non-empty IDs;
- no peer-package dependency.

An Editor utility may be introduced so the behavior is directly testable. A custom `SplashSequence` Inspector may call that utility while retaining the normal visible serialized authoring surface.

## 4. Required Focused Tests

At minimum:

1. one blank entry receives a canonical lowercase 32-character hexadecimal ID;
2. two blank entries receive distinct IDs;
3. an existing non-empty ID is preserved exactly;
4. a second authoring pass makes no further identity change;
5. `SplashSequence.CurrentSchemaVersion` remains `1`.

## 5. Project WIP Preservation

Do not stage, overwrite, restore, or delete:

```text
Assets/EchoDevGames/SuiteShowcase/FirstLight/Configuration/SplashSequence.asset
Assets/EchoDevGames/SuiteShowcase/FirstLight/Art/**
```

until the hotfix implementation is proven and the public Inspector is used to repair the blank identities.

## 6. Manual Acceptance

After focused tests:

1. select the existing project-owned `SplashSequence.asset`;
2. allow the normal Inspector to process the two entries;
3. save;
4. verify both serialized `entryId` values are non-empty canonical IDs;
5. press Play from `FirstLight_Showcase_Boot`;
6. confirm `ELAUNCH-SPLASH-001` no longer blocks those entries.

## 7. Stop Point

If the public Inspector still requires hidden fields, YAML editing, reflection, runtime mutation, or a wider package change:

**STOP.**

Return to authority review before widening FL-M6-01-H1.
