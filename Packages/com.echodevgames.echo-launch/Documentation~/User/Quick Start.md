# First Light Quick Start

First Light gives a Unity project one controlled startup path: optional splash presentation, ordered startup steps, launch reporting, and handoff to one initial destination.

## 1. Open Setup

In Unity, open:

```text
Tools > Sperk's Forge > First Light > Setup
```

Setup is preview-first. Configure the request, press **Refresh Plan**, inspect the operations/diagnostics, then Apply only when the plan is Ready.

## 2. Choose Project Paths

Select:

- a project-owned root under `Assets/**`;
- a project-owned Boot scene path beneath that root;
- an existing destination scene;
- a Build Settings policy.

The default proposed root is:

```text
Assets/EchoDevGames/FirstLight
```

The default Build Settings policy is `Add If Missing At End`.

## 3. Choose Foundation Asset Resolution

Setup exposes:

```text
Foundation
  Asset Resolution .... Reuse Compatible Assets
                         Create Project-Owned Setup
```

### Reuse Compatible Assets

This is the backward-compatible default. If a requested target is missing and exactly one compatible eligible project asset exists elsewhere, Setup may reuse it.

### Create Project-Owned Setup

Use this when the requested root should own an independent First Light foundation. Missing requested Configuration, LaunchDestination, StartupSequence, optional SplashSequence, and EchoLaunchRoot prefab targets are created beneath the requested root instead of being replaced by compatible off-root candidates.

Existing compatible requested targets remain authoritative. Incompatible requested targets still block. The explicitly selected destination scene may still be reused.

## 4. Optional Splash Sequence

Enable **Create Splash Sequence** to create and configure a new project-owned sequence during Setup.

Sequence presentation controls include:

```text
Mode ................ Splash Only / Splash + Status
Background .......... project-owned color
Allow Advancement ... Yes / No
```

Each splash can author:

- Image
- optional Audio Intent (`PreferredAudioClip` metadata only)
- Display Label
- Fade In
- Hold
- Fade Out
- Minimum Display
- Motion: None / Pulse
- Pulse Maximum Scale / Cycle Seconds
- Advance: Automatic / Skippable After Minimum / Wait For Input After Minimum

First Light does **not** play the preferred audio clip. The reference records future playback intent for a separate audio system/bridge.

Blank splash entry identities are generated by Editor authoring tooling. Existing non-empty identities are preserved.

## 5. Preview, Apply, Repeat

1. Press **Refresh Plan**.
2. Resolve any blockers before applying.
3. Press **Apply Plan...** and confirm.
4. Inspect the created/reused paths and Build Settings result.
5. Refresh and Apply the identical request again.

A converged project returns:

```text
Status: NoChanges
Created paths: None
```

Setup does not overwrite a reused SplashSequence with creation-time authoring. If you need a new authored sequence while compatible assets already exist elsewhere, choose **Create Project-Owned Setup**.

## 6. Run the Boot Scene

Play the configured Boot scene. The normal successful order is:

```text
claim launch authority
→ validate configuration / splash / startup / destination
→ optional splash presentation
→ ordered startup sequence
→ destination transition
→ Completed launch report/event
```

A project may use an empty valid StartupSequence for the smallest happy path.

## 7. Development Tools

First Light also provides:

- **Validator** — read-only project-health inspection;
- **Repair** — explicit current-schema reconciliation for narrowly proven drift;
- **Direct Scene Development Initializer** — development-only direct-scene entry;
- **Launch Simulator** — Editor-only deterministic startup-step scenarios;
- **First Light Standalone Test Lab** — separately importable UPM sample.

See the package README and Developer documentation for their exact boundaries.

## 8. Reference Gallery in The Sperk's Forge Repository

The suite repository contains project-owned reference examples under:

```text
Assets/EchoDevGames/SuiteShowcase/First Light Gallery/
```

They are examples, not package defaults or dependencies. Consumer projects should use their own branding, scenes, content, and destination.

## Current Qualification Boundary

The in-repository package implementation, Standalone Test Lab, and Reference Gallery are proven. Separate clean-project reproduction and release qualification are not claimed by this Quick Start.
